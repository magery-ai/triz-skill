# Multi-run eval results, 2026-10-21

All 13 cases in `evals/cases/`, run 3 times with the skill and 3 times
without it: 78 conversations and 39 blind comparisons. This replaces the
one-run-per-arm numbers of the [first full run](2026-10-21.md) and the
[autonomous re-run](2026-10-21-autonomous.md).

## Method

- **Runs.** Same as the first full run. For each arm and run, a fresh agent
  played both the assistant and the persona user from the case file. The
  persona answered only what the assistant asked; answers the case file did
  not cover were marked `[improvised]`. Both arms got the case with the answer
  key (`expected_contradictions`, `checks`) removed. Agents without the skill
  could not read this repository or the web. Every run, the baseline
  included, is new; nothing is reused from earlier runs.
- **Grading.** For each case and run number, a separate agent saw the two
  transcripts as A and B in a random order (seed 20261021; the skill was A
  in 22 of 39 pairs). It did not know which one had the skill, and graded
  each against the case checks and the outcome items: root conflict,
  context use, measurable finish, risk signal, resolves the conflict, next
  steps and reaches the target. Then it said which plan it would act on.
  The protocol is the same as before.
- **Version.** Skill at v1.2.0 (commit `ee8a51f`).
- **Turns** are user replies after the opening message, counted from the
  transcripts.

## What it means

- The skill's result is stable: across 3 runs it passed 370 of 372 items and
  never missed a dated target, a risk threshold or owned next steps.
- The grader preferred the skill's plan in 38 of 39 comparisons, including
  all 9 autonomous runs. The autonomous fix in v1.2.0 holds.
- Without the skill, the core idea is often as good: both arms usually
  reached the same main fix, and the baseline resolved the conflict in 36
  of 39 runs. What it lacks is the plan around the idea. It set a dated
  target in 4 of 39 runs, a risk threshold in 6 and owned steps in 11.
- The one loss (sw-cache-freshness, run 2) went to a baseline with deeper
  engineering (an outbox for cache refresh, handling the race on cache
  clear) in fewer turns, although the skill passed every item and the
  baseline failed four.
- The cost is unchanged: about 5 more user replies, for a final plan about
  half as long.

## Change from the one-run numbers

The skill's numbers match the first run (123 of 124 then, 123.3 now). The
baseline scored lower this time (71 of 124 on average, against 92 in the
first run, which was also outside this run's range). In these runs the
baseline asked fewer questions (median 1 reply, against 3) and so had fewer
facts to build a dated, owned plan from. One baseline run per case was not
enough to see that spread, which is why the README now reports these
numbers.

## Limits

- The same model family played the assistant, the user and the grader.
- The persona users are simulated, and some answers were improvised.
- Several outcome items (dated target, risk threshold, owners) are things
  the skill's template always asks for, so they favour its format. The
  grader preference is the fairest single number, and even there graders
  noted that the baseline often had the stronger engineering detail.
- Transcripts and grades are in the project folder `evals-multi/`, not in
  this repository.
