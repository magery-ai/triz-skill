# Scenario eval results, 2026-10-21

> Superseded by the [multi-run results](2026-10-21-multirun.md) (3 runs per arm).

All 13 cases in `evals/cases/`, each run once with the skill and once
without it.

## Method

- **Runs.** For each arm, one agent played both the assistant and the persona
  user from the case file. The persona answered only what the assistant
  asked. Agents without the skill could not read this repository. Both arms
  got the case with the answer key (`expected_contradictions`, `checks`)
  removed.
- **Grading.** A separate agent saw the two transcripts as A and B in a
  random order (seed 20261021; the skill was A in 6 of 13 cases). It did not
  know which one had the skill. It graded each against the case checks and
  these outcome items: root conflict, context use,
  measurable finish, risk signal, resolves the conflict, next steps and
  reaches the target. Then it said which plan it would act on.
- **Version.** Skill at commit `main` after PR #11 (stage 4 expert levers and
  target check, action-first autonomous output).

## What it means

- The skill's main gain is a plan you can check: every plan had a dated
  target and a risk threshold that triggers an action. Without the skill,
  about half the plans had neither.
- The skill costs about three more user replies, and gives a plan about half
  as long.
- Both losses were autonomous cases (no human). In auto-ci the skill passed
  every item, but the grader preferred the baseline's more detailed
  engineering steps. Autonomous output is the next thing to improve.

## Limits

- One run per arm, so a single case can flip.
- The same model family played the assistant, the user and the grader.
- The persona users are simulated, and some of their answers were
  improvised beyond the case file.
